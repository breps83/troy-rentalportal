# Technical Interview: What to Expect

From the assessment specification. See [requirements.md](requirements.md) for the build requirements.

- Submitting the assessment is **not** the technical interview. If the submission moves forward, a
  live technical interview is scheduled to present the solution and walk through the code.
- Have the repository **cloned, built, and running on your own machine** before the interview starts,
  with the database created and seeded. The solution will not be reviewed from GitHub, screenshots,
  or slides.
- Present the running application and the code from an IDE (Visual Studio, Rider, VS Code, etc.)
  while sharing your screen.
- Expect the interviewers to move from file to file in the solution: controllers, view models, and
  views to data access, migrations, and tests. Know your way around the codebase and be able to
  explain any line submitted.
- Be prepared to **debug** the solution if asked, including setting breakpoints and stepping through
  a request.
- Expect in-depth questions about the code produced, the design decisions made, and the trade-offs
  behind them.
- Expect technical questions on the core fundamentals of .NET, C#, ASP.NET Core, and Entity Framework
  Core as they relate to the solution.

## Pre-interview checklist

- [ ] Pull the latest code.
- [ ] Build the solution.
- [ ] Start the application (database created, migrations applied, data seeded).
- [ ] Log in as an **applicant**.
- [ ] Log in as a **property manager**.
- [ ] Run the tests.
